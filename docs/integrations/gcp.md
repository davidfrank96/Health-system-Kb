# Conditional Google Cloud monitoring

[Google Observability pricing](https://cloud.google.com/products/observability/pricing) lists the first **one million time series returned per billing account/month** free for Monitoring read API usage, with charges beyond that. Eligible calls can be charged at least one series even when empty; a request is not necessarily one series. The allowance is shared with other consumers, not reserved for this application.

Automatic collection remains disabled until the billing owner supplies current usage and a conservative forecast/reserve for other workloads. Set an application allowance smaller than documented remaining headroom and include all pages/retries/empty-call minima. Example only: verified remaining 200,000 units, reserve 150,000 for other use → at most 50,000 allocated to this app. This is not evidence that any such allowance exists. If other consumers cannot be bounded or usage evidence is stale, keep the source manual. Local counters cannot guarantee a provider-wide zero bill.

Only already enabled supported Cloud Monitoring APIs and metric descriptors are eligible. Use `roles/monitoring.viewer` or a narrower reviewed role in approved projects; inspect the whole metrics scope. [IAM](https://docs.cloud.google.com/monitoring/access-control). A minimal REST client or official Node client is a later implementation choice, not a new service. Never enable GCP uptime checks, synthetic monitors, log exports, paid agents or new metric ingestion.

Bound resources/dimensions and response series per request before execution, cadence >=15m, one retry within both runtime and usage budget. If the API cannot guarantee a useful upper bound, do not automate that query. Store aggregate observations only; privacy and service environment remain explicit. Candidate CDN/storage metrics depend on verified resource type and descriptors, not generic promises. Tests cover exhausted allowance, reserve races, pagination, descriptor drift, scope leakage, delayed data and safe pause. Manual snapshots use the same canonical units with visible manual source.
